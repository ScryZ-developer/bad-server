## О проекте

Проект WebLarek - интернет-магазин с каталогом товаров, корзиной, оформлением заказов и админ-панелью. В рамках проектной работы проведён аудит безопасности и устранены уязвимости: XSS, CSRF, NoSQL-инъекции, ReDoS, path traversal, переполнение буфера и DDoS.

## Подготовка к работе

1. Склонировать репозиторий
2. Запустить Docker

```bash
docker compose up -d
```

3. Наполнить базу данных - инструкция в [.dump/README.md](.dump/README.md)
4. Перейти по адресу http://localhost/ - на странице должны отображаться товары
5. Авторизация: http://localhost/login/
6. Админ-панель: http://localhost/admin/

### Учётные данные по умолчанию

- Администратор: `admin@mail.ru` / `password`
- Покупатель: `user1@mail.ru` / `password1`

> После исправления хеширования паролей (bcrypt) пользователей необходимо пересоздать через регистрацию или повторный импорт данных.

## Реализованные меры безопасности

- **XSS** - экранирование пользовательского ввода на сервере, безопасный вывод комментариев на клиенте
- **CSRF** - токены CSRF для всех изменяющих запросов (`/auth/csrf-token`)
- **NoSQL-инъекции** - валидация и белые списки полей в запросах к MongoDB
- **ReDoS** - экранирование пользовательского ввода в регулярных выражениях
- **Path traversal** - проверка путей при раздаче статики и загрузке файлов
- **DDoS** - rate limiting с настройкой через переменные окружения
- **Переполнение буфера** - лимиты на размер тела запроса и загружаемых файлов

## Переменные окружения

Пример настроек - в `backend/.env.example`.

Ключевые параметры rate limiting:

- `RATE_LIMITED` - включить ограничение запросов (`true`)
- `RATE_LIMIT_POINTS` - число запросов за период
- `RATE_LIMIT_DURATION` - длительность периода в секундах
- `RATE_LIMIT_BLOCK` - время блокировки в секундах
